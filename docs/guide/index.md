# The guide

This directory is the system explained for people: four pages, each
owning one job, and this index, which only routes. If you arrived from a
pointer another project recorded — a provenance line in its goals file
naming the blueprint checkout its artifact set was installed from — this
page is where that pointer lands: start with the overview, because the
other three pages assume its mental model. Agent sessions do not start
here at all; their entry point is `AGENTS.md`, the map kept for exactly
that purpose.

## By role

- Anyone who needs the mental model — `docs/guide/overview.md`: the
  pieces, why each exists, and the loop they form.
- The adopter bringing this to a project — `docs/guide/adopting.md`:
  seeding, the bootstrap session, and what recorded runs say to expect.
- The operator running a repository that has it —
  `docs/guide/operating.md`: cadence, the constant prompts, review
  between rounds, the loop and its halts, the gate, the ladder.
- The builder turning a capability card into a check —
  `docs/guide/implementing.md`: from specification to demonstrated
  enforcement, here or in a client project.

## By task

- Understand why a session reads files instead of remembering —
  `docs/guide/overview.md`.
- Bring the payload to a target repository and bootstrap it —
  `docs/guide/adopting.md`.
- Start a milestone session, author a plan, or drive the watched loop —
  `docs/guide/operating.md`.
- Take one card from `specced` to `enforced` —
  `docs/guide/implementing.md`.
- Orient an agent session in this repository — `AGENTS.md`, the map and
  the file every session reads first.
